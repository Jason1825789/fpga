
## 椭圆羽化参数

两套共用同一套参数，与 OSD 布局对齐：

- 椭圆 620 × 360，中心 `(320, 250)`
- 4 倍超采样抗锯齿 + 10px 高斯羽化
- 椭圆外 `#F0F0F0`
- 顶部让开时间戳面板（`y=48`）22px，底部让开红条字幕（`y=460`）30px

## 地名标签（两种样式）

两版排版结构相同，只有中文字体不同：

```
              万寿山      ← 中文，#102030
        ────────────      ← 细线 2px，#96A2AC，宽度跟中文
      Longevity Hill      ← Times 12px，#566878
```

- 整体右对齐，距右边 24px
- **细线宽度固定跟中文，不跟英文**。否则 `Tower of Buddhist Incense` 这类长名会把线
  拉长，8 张轮播时线长来回跳。长英文改为向左自然延伸
- 中文色与 OSD 状态条、时间戳同为 `#102030`，整屏是一套设计
- 选位依据：右上角整片浅灰底（椭圆在 `x=616` 处顶边已低到 `y≈197`），
  不压风景，也不与左侧状态条、时间戳冲突

### 有名字1：隶书

隶书 32px（`simli.ttf`），中文顶部距画面顶 11px，细线在 `y=50`，英文 `y=55`。

选它的原因：试过华文行楷、隶书、华文隶书、方正姚体、楷体、思源黑。行楷在 30px
会散，姚体偏现代，楷体略端正；隶书既有书法感，笔画又够粗、小尺寸不糊，配皇家园林对。

### 有名字2：宋体骨架定制艺术字

华文中宋 34px（`STZHONGS.TTF`），中文顶部 `y=10`，细线在 `y=49`，英文 `y=53`。

对应用户描述的四个特征，全部在 `artfont.py` 里参数化：

| 诉求 | 实现 |
|---|---|
| 宋体骨架 | 华文中宋（标题宋，横细竖粗天然明显） |
| 笔画修长 | 102px（3x）渲染后垂直拉伸 `STRETCH_Y=1.10` |
| 转折精致 | 3x 超采样 + LANCZOS 降采样 |
| 少量书法笔意 | 整体右倾 `SHEAR=-0.03`（以底边为支点） |
| 字距均匀 | 等宽字框取最宽字，逐字居中，`tracking=0.12` |

两个反直觉的坑，已在代码注释里标明：

1. **渲染倍率不是越高越好**。用 240px（7x）渲染再缩到 34px，笔画会发灰、`寿`字内部
   横画粘连；102px（3x）既保留衬线细节又不丢锐度。
2. **不要按字高压缩宽度**。早期实现里"缩放后宽度超过字高就压到 34px"，把 `寿` 横向
   压扁、笔画糊成一块。正确做法是只按高度等比缩放，字框取最宽字。
3. **不要做竖笔定向膨胀**。设想是把竖笔加粗做出"横细竖粗"，实测 `a - 水平腐蚀` 会
   同时选中横画两端，膨胀后横画被拉长，`万` 的上横会伸出去。宋体本身已够对比，关掉。
4. **不能逐字按墨迹高度缩放**。`·` 的墨迹只有 17px 高，按字高归一化会被放大成一个
   30px 的实心黑点，全角括号也会变形。正确做法是**整行一次性排版**：逐字按字体自身
   advance 落笔，整行按"国"字墨迹高度统一缩放。

02 与 08 的地名由 `gen_display_bmp.py` 里的 `SERIF_NAME_OVERRIDE` 单独指定（宋体版专用），
隶书版 `有名字1` 不受影响：

```python
SERIF_NAME_OVERRIDE = {"02.bmp": "佛香阁·暮", "08.bmp": "佛香阁·晨"}
```

地名是**画进 BMP 的，不是 OSD 图层**，所以零 RTL 改动、切图时地名跟着走；代价是改名要重生成图片。

## 重新生成

```bash
cd E:/workbuddy/6/doc/TF卡图片_颐和园
D:/Python311/python.exe gen_display_bmp.py            # 隶书版 → 有名字1/
D:/Python311/python.exe gen_display_bmp.py --serif    # 宋体版 → 有名字2/
D:/Python311/python.exe gen_display_bmp.py --no-tag   # 无地名 → 椭圆羽化无名字/
D:/Python311/python.exe update_previews.py 有名字2 "宋体骨架艺术字"   # 刷新预览
```

脚本从 `源图/` 走完整流程：裁切 → 椭圆羽化 → 加地名 → BMP。地名与英文在脚本顶部
`PICKS` 表里改。已验证裁切/羽化参数与历史版本逐像素一致，只有标签区域会变。

要调椭圆大小、羽化强度、标签字号，改脚本顶部的常量即可（`EW/EH/CX/CY/FEATHER`、
`CN_SIZE/EN_SIZE/RULE_DY`；宋体版为 `SERIF_CN_SIZE/SERIF_CN_TOP/SERIF_TRACKING`）。

## 拷卡顺序（当前卡内布局，2026-11-02 16:15 重排）

**播放顺序由文件在卡上的物理写入顺序（起始簇 LCN 递增）决定，不是文件名排序。**
代码不解析文件名，只按扇区扫描找到 BMP 的先后顺序播 —— **所以改文件名无效，必须重写卡。**

当前顺序按"全景点题 → 佛香阁由远及近且晨→暮 → 长廊 → 石舫全景+近景 → 十七孔桥 → 廓如亭收尾"
排列，同时把同一区域的十七孔桥与廓如亭排在一起：

| 播放位 | 文件 | 画面 | 起始 LCN |
|---|---|---|---|
| 第1张 | `01.bmp` | 万寿山（全景点题） | 0x4 |
| 第2张 | `08.bmp` | 佛香阁·晨（远景） | 0x75 |
| 第3张 | `02.bmp` | 佛香阁·暮（特写） | 0xE6 |
| 第4张 | `07.bmp` | 长廊 | 0x157 |
| 第5张 | `04.bmp` | 石舫（全景） | 0x1C8 |
| 第6张 | `05.bmp` | 清晏舫（近景） | 0x239 |
| 第7张 | `03.bmp` | 十七孔桥 | 0x2AA |

**重写卡的正确做法**：先删光卡上全部 BMP，再**按上表顺序一个一个拷**（不要全选拖拽，顺序不可控），
拷完用 `gen_card_order_sheet.py I:/` 出核对图 + `fsutil file queryextents` 确认 LCN 严格递增。

卡里**不要混放其它 BMP**。代码上限 8 张（`SCAN_TARGET_COUNT = 8`，`img_sector0..7`，3 位索引）。
