## 三条硬约束（不满足会导致字显示错乱）

### 1. 总字符数 ≤ 16

字符位置号是 4 位（`char_sel[3:0]`），最多 16 个位置。超过就要把索引位宽扩到 5 位，
连带改 `pos_to_font`、`FONT_ALL` 位选、`c_sel`，风险成倍上升。**不要轻易突破。**

### 2. 必须「ASCII 在前，汉字在后」

排版不是按字符实际宽度，而是按**位置号**分两种格宽：

```
位置 0 ~ N-1  → 12px 格（数字、字母、冒号、减号）
位置 N ~ 15   → 16px 格（汉字）
```

`pos_of()` 是一条比较器链，按 `dx` 落在哪个格返回位置号；`pos_xbase()` 给出该格起点。
两者必须在切分点上一致，不能出现「汉字在前、数字在后」。

### 3. 切分点变了要同步改三处

如果 ASCII 字符数不是 10（当前值），必须同步修改 `osd_engine.v` 里：

| 位置 | 内容 |
|---|---|
| `pos_xbase()` | 16 个 case 分支的起始列 |
| `pos_of()` | 比较器链的 15 个阈值 |
| `SCROLL_W` / `SCROLL_PERIOD` | 总宽 = ASCII数×12 + 汉字数×16；周期 = 总宽 + 640 |

`SCROLL_PERIOD` 是 11 位，上限 2047，总宽不超过 1407 都安全。

## 为什么字模要重做

`font_rom.v` 里存的是 **16×16 点阵常量**（`FONT_ALL`），不是字符串。
字库里没有的字，板上不会「找不到字体」，而是直接显示空白或乱码。

脚本按以下规格渲染，与原工程 2026-10-05 版一致：

- 字体 `C:/Windows/Fonts/NotoSansSC-VF.ttf`，字重 500
- 4 倍超采样（64×64）→ LANCZOS 缩回 16×16 → 阈值 >110 二值化
- ASCII 盒 11×12、汉字盒 15×15，均 1px 左边距
- **ASCII 按基线对齐**（冒号、减号位置才正确），汉字按字框顶对齐
- 缩放后宽度不足格宽一半的字符（标点）在格内居中，否则左对齐

位序：字面量最右一组 = `bits[15:0]` = row0（最上行），每行 bit15 = 最左列。
**写错就是上下颠倒**，改完务必跑一次反解析校验。

## 生成后必须验证的三件事

### 1. 字模位序（Python 反解析）

从 `font_rom.v` 解析 `FONT_ALL`，与 `make_glyph()` 结果逐位比对，必须 0 差异。
脚本的 `--preview` 只出图，位序校验需要单独跑（见本文末尾脚本片段）。

### 2. RTL 排版（ModelSim）

```bash
cd E:/workbuddy/6/verification/spectrum_mvp_20261101/sim_clock
/d/modelsim/win64/vlog.exe -work work \
  E:/workbuddy/6/src/user_source/hdl_source/font_rom.v \
  E:/workbuddy/6/src/user_source/hdl_source/osd_engine.v \
  tb_text_strip.v
/d/modelsim/win64/vsim.exe -c -novopt -do "run -all; quit -f" tb_text_strip
```

`tb_text_strip.v` 把 `dx=0..215`、`dy=0..15` 全扫一遍写入 `strip.txt`，
再用 Python 与预期点阵比对，必须是 0 差异。这一步验证的是 `pos_of` / `pos_xbase` /
`c_col` 的排版逻辑，与字模无关。

### 3. 布线后时序

改字模不改时序结构，寄存器数应当**完全不变**。若寄存器数变了，说明动到了别的地方。

## 已踩过的坑

**`c_col` 位宽**：原来是 `wire [3:0] c_col`，直接连到 `font_rom` 的 `[4:0] col` 端口。
TD 会报 `PCDPC` 位宽告警，ModelSim 仿真时高位为 X，导致**字形输出全 X**（板上正常，
因为综合工具做零扩展，但仿真结果不可信）。已改成显式补零：

```verilog
wire [3:0]  c_col4 = dx[3:0] - c_xbase[3:0];
wire [4:0]  c_col  = {1'b0, c_col4};
```

**4 位模减不能简单拓宽**：`dx[3:0] - c_xbase[3:0]` 是模 16 运算，4 位时 `0-8=8`（正确），
改成 5 位减法则 `0-8=24`（错误）。必须保持 4 位减法，再把结果补零到 5 位。

**脚本会重写整个文件**：`font2verilog.py` 只替换字模与映射表，文件后半段
（①②③④⑤⑥ 逻辑）从 `font_rom_tail.txt` 模板取。首次运行时自动从现有
`font_rom.v` 截取；若模板损坏，删掉它并用未污染的 `font_rom.v` 重跑。
